| 項目 | 內容 |

---

## 1. 背景與目的

目前系統能透過 RTSP/Webcam 影像偵測「人是否在座位上」，並在連續工作達門檻時提醒休息。實際使用後發現數項影響可用性的問題：使用者看不出系統當前判斷、無法方便地離開關閉、提醒流程的按鈕語意不清、暫停功能行為異常、狀態文字資訊不足，以及 RTSP 預覽有延遲與破圖。

本文件彙整 8 項需求與對應的預期行為、驗收標準與涉及檔案，作為後續實作（撰寫實作計畫）的依據。

---

## 2. 名詞定義

| 名詞 | 說明 |
|---|---|
| present | 經去抖動（`debounce_count`）後判定「ROI 內是否有人」的布林值 |
| 工作門檻 `work_threshold` | 連續工作達此時間即觸發提醒 |
| 重置門檻 `reset_threshold` | 工作中離座超過此時間視為本輪工作結束 |
| 必需休息 `required_rest` | 一次「完整休息」所需的時間 |
| 自動離開 vs 手動暫停 | 自動＝偵測到人走開；手動＝使用者主動按暫停鈕。兩者為不同狀態 |

## 3. 現況問題摘要（實作前確認過的根因）

| # | 需求 | 現況根因（程式碼層級） |
|---|---|---|
| 1 | 顯示有沒有人 | `worker` 有發出 `presence_changed`，但 `MainWindow.on_presence_changed` 直接 `del present` 丟棄，畫面無任何指示 |
| 5 | 暫停時間照跑 | 暫停時 worker 迴圈 `sleep` 後 `continue`，未呼叫 `timer_engine.update()`，`_last_t` 停在暫停前；繼續後第一次 `update()` 的 `dt = now − _last_t` 會把整段暫停時間一次加進工作時間 |
| 7 | 一直顯示「提醒中」 | `TimerState` 只有 待機/工作中/短暫離開/提醒中，**沒有「休息中」**；休息倒數期間狀態仍停在 REMINDING |
| 4 | 我知道了 vs 關閉 | `reset_mode: detection` 下，兩顆按鈕實際都只是關閉視窗（`on_reminder_dismissed` 在 detection 模式幾乎無作用），效果無差異 |
| 8 | RTSP 延遲/破圖 | 預覽與偵測共用同一迴圈，受 `detection.interval_sec`（預設 1.0s）節流；每秒只 `read()` 一次，取到的是解碼緩衝區的舊影格，造成延遲累積與部分影格破圖 |

## 4. 核心設計：狀態機

重新定義計時狀態集，新增「休息中」與「已暫停」。狀態文字顯示於時間旁。

| 狀態 | 顯示文字 | 觸發條件 |
|---|---|---|
| IDLE | 待機 | 尚未開始；或休息完成後等待「歡迎回來」確認期間 |
| WORKING | 工作中 | 偵測到人、計時進行中 |
| AWAY | 短暫離開 | 工作中暫時離座，未達重置門檻（**自動**） |
| REMINDING | 提醒中 | 工作達門檻、提醒彈窗顯示中 |
| **RESTING（新增）** | **休息中** | 於提醒中按下「開始休息」後 |
| **SUSPENDED（新增）** | **已暫停** | 使用者**手動**按暫停鈕（凌駕其他狀態顯示） |

> 「短暫離開（AWAY）」是自動偵測人走開；「已暫停（SUSPENDED）」是手動暫停。兩者分開，文字不同。

### 完整生命週期

```
待機 ──偵測到人──▶ 工作中 ──達工作門檻──▶ 提醒中
                                          │（彈窗：單一「開始休息」鈕）
                                          ▼
                                        休息中（倒數 required_rest）
                                          │（完成一次完整休息 且 回到座位）
                                          ▼
                          彈出「歡迎回來，開始新一輪？」確認窗
                                          │（按下確認）
                                          ▼
                                        工作中（新一輪）

* 確認前狀態維持「待機」、不計時。
* 任一狀態下按手動暫停 → 已暫停（凍結）；再按繼續 → 回到原狀態接續。
```

## 5. 逐項需求

### 需求 1：顯示「有沒有人」狀態

- **現況**：`present` 被丟棄，畫面無指示。
- **需求**：在主視窗頂部、現有「已連線」徽章旁，新增**人體狀態徽章**。
- **預期行為**：
  - 偵測到人：🟢 綠點 ＋ 文字「有人」。
  - 未偵測到人：⚪ 灰點 ＋ 文字「無人」。
  - 以去抖動後的 `present` 為準（避免閃爍）。
- **驗收標準**：
  - 人進入/離開 ROI 後，徽章在去抖動延遲內正確切換。
  - 連線中斷時徽章不誤判為「有人」（顯示無人或維持最後狀態，由連線徽章另外表達）。
- **涉及檔案**：`src/ui/main_window.py`（改寫 `on_presence_changed`）、`src/app/worker.py`（已有 `presence_changed`）、新增人體狀態徽章元件（參考 `src/ui/widgets/connection_badge.py`）、`src/ui/strings.py`（新增文字）。

### 需求 2：離開按鈕（完全結束程式）

- **需求**：在 ActionBar 新增一顆「離開」按鈕，按下＝**完全結束程式**。
- **預期行為**：
  - 等同系統匣「結束」：停止偵測執行緒、寫入本輪工作紀錄、釋放資源、關閉應用程式。
  - 按下後先跳**二次確認對話框**（防誤觸），確認後才結束。
  - 按鈕採紅色 danger 樣式，置於 ActionBar 右側（靠近「設定」）。
- **驗收標準**：
  - 按下並確認後，程序完全結束（無殘留背景執行緒），且本輪工作時間有寫入紀錄。
  - 取消二次確認則回到原狀態，不結束。
- **涉及檔案**：`src/ui/widgets/action_bar.py`、`src/main.py`（連到 `app.quit` / 既有 `_shutdown_worker_thread`）、`src/ui/strings.py`。

### 需求 3：休息完回來的「確認彈窗」

- **需求**：使用者**完成一次完整休息後回到座位**時，彈出「歡迎回來」確認窗；**按確認後才開始新一輪計時**。
- **預期行為**：
  - 觸發條件：狀態為「休息中」且已達成一次完整休息（見需求對應的休息計算模式），其後偵測到人回到座位。
  - 彈窗內容：標題「歡迎回來」、訊息提示已休息完成、單一「開始新一輪」確認鈕。
  - **未確認前**：狀態維持「待機」、**不計時**，彈窗持續顯示直到確認（不自動視為確認）。
  - 短暫離開後回來（未達成完整休息）**不**觸發此彈窗，依狀態機自動續計。
- **驗收標準**：
  - 完成完整休息→回座→彈窗出現；在按下確認前，時間不前進、狀態為「待機」。
  - 按下確認後，立即開始「工作中」新一輪，計時自 0 起算。
  - 短暫離開（未達休息）回座不會出現此彈窗。
- **涉及檔案**：`src/timer_engine.py`（新增休息完成 → 等待確認的狀態流轉與事件）、`src/app/worker.py`、`src/types.py`（新增狀態/事件型別）、新增/調整確認彈窗（參考 `src/reminder/`）。

### 需求 4：提醒彈窗按鈕語意（單一「開始休息」）

- **現況**：detection 模式下「我知道了」與「關閉」效果幾乎相同，使用者看不出差異。
- **需求**：提醒彈窗改為**單一「開始休息」按鈕**，移除混淆的第二顆按鈕。
- **預期行為**：
  - 按「開始休息」→ 進入「休息中」狀態並開始休息倒數。
  - 以視窗右上 X 關閉彈窗 → 視為暫不處理：維持「提醒中」，於 `repeat_interval` 後再次提醒。
- **驗收標準**：
  - 彈窗僅有一顆主要動作鈕「開始休息」。
  - 按下後狀態切換為「休息中」並開始倒數。
  - 關窗後仍會依重複間隔再次提醒。
- **涉及檔案**：`src/reminder/popup.py`、`src/ui/strings.py`。
- **備註**：既有 `reminder.reset_mode`（detection/dismiss/snooze）在統一流程下被簡化或取代，列為待清理項（見第 7 節）。

### 需求 5：暫停／繼續修正（完全凍結）

- **現況（bug）**：暫停期間未更新計時基準，繼續後第一次 `update()` 把整段暫停時間一次加進工作時間，時間「跳一大段」。
- **需求**：暫停＝**完全凍結**——計時停住、偵測停止、提醒停止、預覽畫面定格；繼續後從凍結當下的時間**接續**。
- **預期行為**：
  - 按暫停 → 狀態顯示「已暫停」，工作時間數字停住、進度條不動。
  - 暫停期間不觸發任何提醒、不進行偵測。
  - 按繼續 → 從暫停當下的工作時間接續（不得跳增、不得歸零）。
- **驗收標準**：
  - 暫停 N 秒後繼續，工作時間數字與暫停前一致（不含暫停的 N 秒）。
  - 暫停期間不出現提醒彈窗。
- **涉及檔案**：`src/app/worker.py`（`pause`/`resume`，繼續時重設計時基準）、`src/timer_engine.py`（確保暫停時間不計入 `dt`）。

### 需求 6：編輯 ROI 按鈕視覺回饋

- **現況**：按鈕為 checkable，但無 `:checked` 樣式，按下後介面無明顯變化，使用者以為沒按到。
- **需求**：啟用編輯時，按鈕需有明顯不同的樣式與提示。
- **預期行為**：
  - 啟用中：按鈕切換為明顯「啟用中」樣式（不同底色／邊框），文字由「編輯 ROI」改為「完成編輯」。
  - 啟用中：預覽區顯示提示文字（例如「拖曳以選取偵測區域」）。
  - 結束編輯（再次按下或完成框選）：恢復原樣式與文字、提示消失。
- **驗收標準**：
  - 進入編輯模式後，按鈕外觀與文字明顯改變，預覽出現提示。
  - 退出編輯後外觀還原。
- **涉及檔案**：`src/ui/theme.py`（新增 `QPushButton:checked` 樣式）、`src/ui/widgets/action_bar.py`、`src/ui/widgets/preview_view.py`、`src/ui/strings.py`。

### 需求 7：狀態文字顯示完整狀態集

- **現況**：僅 待機/工作中/短暫離開/提醒中；休息倒數時仍顯示「提醒中」。
- **需求**：採用第 4 節完整狀態集，新增「休息中」「已暫停」。
- **預期行為**：時間旁的狀態文字依狀態機即時更新；手動暫停時顯示「已暫停」並凌駕其他狀態。
- **驗收標準**：
  - 休息倒數期間顯示「休息中」（非「提醒中」）。
  - 手動暫停顯示「已暫停」；自動離座顯示「短暫離開」，兩者可區分。
- **涉及檔案**：`src/types.py`（`TimerState` 擴充）、`src/ui/strings.py`（`STATE_TEXT`）、`src/ui/widgets/status_strip.py`、`src/timer_engine.py`。

### 需求 8：RTSP 渲染延遲與破圖

- **現況**：預覽跟著每秒一次的偵測迴圈，讀到的是緩衝區舊影格 → 延遲累積、部分影格破圖。
- **需求**：**拆分擷取與偵測**，降低延遲並改善破圖。
- **預期行為**：
  - 獨立高頻擷取執行緒持續解碼，僅保留「最新影格」（丟棄積壓舊格），預覽以較高頻率即時渲染。
  - 解碼緩衝設為最小（`CAP_PROP_BUFFERSIZE = 1`），避免讀到積壓影格。
  - 偵測維持約每秒一次，自「最新影格」取樣，不再節流預覽。
- **驗收標準**：
  - 預覽延遲明顯下降（接近即時），破圖情況明顯減少。
  - 偵測頻率維持約每秒一次，CPU/GPU 負載不顯著惡化。
- **涉及檔案**：`src/capture/video_source.py`、`src/app/worker.py`、`src/ui/widgets/preview_view.py`。
- **未來選項（非本次範圍）**：`rtsp_transport=tcp`、硬體解碼、關鍵影格容錯等進一步消除破圖的手段。

## 6. 設定（config.yaml）變更

| 設定 | 型別/值 | 預設 | 說明 |
|---|---|---|---|
| `timer.rest_count_mode`（新增） | `presence` / `fixed` | `presence` | 休息倒數計算方式：`presence`＝必須偵測到離座才倒數 `required_rest`（中途回座暫停倒數）；`fixed`＝按下「開始休息」即固定倒數，不論人在不在 |

> 兩種模式皆需支援，使用者可依需求切換。

## 8. 非功能需求與風險

- **效能**：RTSP 擷取改為獨立執行緒後，需確保影格緩衝不無限增長、執行緒可正確釋放（程式結束、來源重連時）。
- **執行緒安全**：最新影格在擷取執行緒與偵測/渲染之間共享，需以鎖或原子替換避免讀到半張影格。
- **相容性**：Webcam 來源沿用同一拆分架構，行為需與 RTSP 一致。
- **回歸**：暫停修正、狀態機擴充需補上對應單元測試（參考既有 `tests/test_timer_engine.py`、`tests/test_worker.py`）。
