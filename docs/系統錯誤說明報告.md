### 系統錯誤說明報告

#### 1. 狀態列時間顯示邏輯異常（時間軸不同步與跳動）

系統在切換不同狀態（工作中、提醒中、已暫停）時，其後方跟隨的計時器並未正確反映「該狀態的持續時間」，且出現邏輯錯亂與時間跳動的現象：

* **狀態切換未歸零：** 當系統由「工作中」切換至「提醒中」時，計時器並未重新計算提醒時間，而是直接繼承或繼續累加總時間。
* **暫停時的數值突變：** 使用者在點擊「暫停」時，狀態從「工作中 01:17」瞬間跳變為「已暫停 01:42」。計時器似乎抓取了系統的總運行時間（或系統時鐘的絕對差值），而非凍結在暫停當下的工作時間，亦非從零開始計算暫停時間。
* **恢復運行時的時間回溯：** 點擊「繼續運行」後，經歷短暫的「啟動中」，狀態在 01:52 變為「提醒中 01:34」，隨後在 01:54 跳至「工作中 01:36」。時間軸出現前後不一致與回溯的錯誤。

#### 2. 提醒通知文字參數缺失（顯示為 00 分鐘）

* 當系統觸發休息提醒的彈出視窗時，對話框的文字皆顯示為：「**請休息一下 - 已經工作00分鐘了**」。
* **錯誤原因：** 傳遞給提示視窗的「已工作時間」變數未能正確帶入或格式化，導致無論實際經過多久，數值皆固定顯示為 `00`。

#### 3. 後端執行緒與資料庫衝突（SQLite Thread-Safety Issue）

背景終端機（Terminal）持續印出嚴重的 Python 錯誤，這是導致系統狀態可能無法正確儲存或更新的主因：

* **錯誤訊息：** `sqlite3.ProgrammingError: SQLite objects created in a thread can only be used in that same thread.`
* **錯誤原因：** 系統使用了多執行緒（Multi-threading），但共用了同一個 SQLite 資料庫連線物件。SQLite 預設不允許跨執行緒操作同一個連線。這會導致背景的記錄功能（如 `logging_store.py`）崩潰，進而引發 UI 狀態無法與後端資料庫同步。

#### 4. 影像串流連線與解碼警告

背景終端機同時記錄了多筆與影像處理相關的錯誤與警告：

* **RTSP 串流超時：** `ffmpeg_interrupt_callback stream timeout triggered after 30030.270000 ms`。代表 RTSP 影像串流在連線或傳輸過程中發生了超過 30 秒的延遲或中斷。
* **解碼錯誤：** 終端機顯示大量的 `error while decoding MB` 以及 `co located POCs unavailable` 等訊息，且伴隨 `png error: IDAT: CRC error`。這通常是由於 RTSP 網路封包遺失（Packet Loss）或不穩定的視訊流所造成的畫面破圖或解碼失敗警告。
