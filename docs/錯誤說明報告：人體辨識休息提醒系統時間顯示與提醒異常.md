# 錯誤說明報告：人體辨識休息提醒系統時間顯示與提醒異常

## 一、測試概要

測試影片顯示系統為「人體辨識休息提醒系統」，以 Python 程式啟動，影像來源使用 RTSP。影片中主要觀察到「工作中」、「提醒中」、「提醒彈窗」、「今日工作統計」與背景錯誤訊息存在多項異常，尤其是時間顯示與提醒內容不一致。

## 主要錯誤項目

### BUG-001：提醒彈窗顯示「已連續工作 0 分鐘」不正確

**嚴重程度：高**

**實際結果：**
系統進入提醒狀態時，主畫面顯示「提醒中 00:30」，但彈出的提醒視窗文字顯示「你已連續工作 0 分鐘。」。

**預期結果：**
提醒內容應正確顯示已連續工作的時間。例如設定工作門檻為 0.5 分鐘時，應顯示「30 秒」、「0.5 分鐘」或依產品規格顯示「1 分鐘」，不應顯示為「0 分鐘」。

---

### BUG-002：「工作中」切換到「提醒中」後，時間顯示語意不清且疑似延續錯誤

**嚴重程度：高**

**實際結果：**

* 約 00:25：狀態顯示「工作中 00:01」
* 約 00:53：狀態顯示「工作中 00:29」
* 約 00:54：狀態切換為「提醒中 00:30」
* 約 02:35：仍顯示「提醒中 02:08」

狀態從「工作中」切換為「提醒中」後，時間沒有重新歸零，而是沿用工作計時繼續累加。

**預期結果：**
系統應明確區分不同狀態的時間意義：

* 若「提醒中」代表提醒已持續多久，切換狀態後應從 00:00 開始計算。
* 若「提醒中」仍代表連續工作總時長，畫面文字應改為「已連續工作 00:30」或「超時 00:00」，避免使用者誤解。

**影響：**
使用者無法判斷畫面上的時間是「工作時間」、「提醒持續時間」還是「超時時間」，會影響休息提醒判斷與使用信任度。

---

### BUG-003：「今日工作」累計時間未隨目前工作狀態更新

**嚴重程度：中**

**實際結果：**
畫面從初始狀態、工作中、提醒中，到暫停狀態，「今日工作」皆維持顯示為「14 分鐘」。影片中已連續記錄超過 2 分鐘，但今日工作累計值未增加。

**預期結果：**
若「今日工作」代表當日累計工作時間，應在工作期間持續更新，或至少在狀態切換、提醒觸發、暫停時更新一次。

**影響：**
統計資料與目前工作狀態不一致，使用者會誤以為系統沒有正確記錄工作時間。

---

### BUG-004：背景出現 SQLite 跨執行緒錯誤

**嚴重程度：高**

**實際結果：**
命令提示字元中出現錯誤：

`sqlite3.ProgrammingError: SQLite objects created in a thread can only be used in that same thread`

錯誤堆疊顯示發生於：

* `worker.py`
* `logging_store.py`
* `connection.close()`

**預期結果：**
系統不應在正常啟動、關閉或切換流程中出現未處理例外。SQLite 連線應在建立該連線的同一執行緒中使用與關閉，或透過安全的資料庫寫入佇列處理。

**影響：**
可能造成工作紀錄、休息紀錄、今日統計資料寫入失敗，並可能與「今日工作」未更新問題有關。

---

### BUG-005：RTSP / H.264 影像串流解碼錯誤與逾時

**嚴重程度：中**

**實際結果：**
命令提示字元中多次出現：

* `RTP: PT=60: bad cseq`
* `error while decoding`
* `co located POCs unavailable`
* `Stream timeout triggered after 30030.270000 ms`
* `libpng error: IDAT: CRC error`

**預期結果：**
系統應穩定處理 RTSP 串流，若串流不穩定，應在 UI 顯示明確狀態，例如「串流中斷」、「重連中」、「影像解碼異常」，而不是只在背景輸出錯誤。

**影響：**
影像串流錯誤可能導致人員偵測延遲、狀態誤判，進而影響工作時間與提醒時間的準確性。

## 四、重現步驟

1. 啟動系統：`python -m src.main`
2. 確認影像來源為 RTSP。
3. 設定工作門檻為 0.5 分鐘。
4. 保持人員出現在攝影機畫面中。
5. 觀察主畫面狀態由「待機」切換為「工作中」。
6. 等待約 30 秒觸發休息提醒。
7. 檢查主畫面的「工作中／提醒中」時間、提醒彈窗內容與今日工作統計。

## 五、建議修正方向

1. 將工作時間、提醒時間、休息時間拆成獨立計時來源，避免不同狀態共用同一顯示欄位。
2. 對小於 1 分鐘的時間不要直接轉整數，應顯示秒數或保留小數，例如「30 秒」或「0.5 分鐘」。
3. 「提醒中」狀態應明確定義：是提醒持續時間、超時時間，還是連續工作時間。
4. 今日工作累計應在工作期間或狀態切換時正確更新。
5. SQLite 連線需改為執行緒安全設計，例如每個執行緒各自建立連線，或集中由單一資料庫寫入執行緒處理。
